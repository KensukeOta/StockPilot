## 2. 本書の目的

本書は、StockPilotのプロジェクト企画書に基づき、想定顧客企業のビジネス課題を解決するために必要な業務要件および業務ルールを定義することを目的とする。

本書で定義した業務要件は、後続の業務フロー定義、機能要件定義、非機能要件定義、基本設計およびテストの基礎とする。

なお、想定顧客企業および業務上の要求は架空の設定であり、実際の顧客へのヒアリングに基づくものではない。

## 3. 対象業務

### 3.1 対象企業

プロジェクト企画書で定義した株式会社リテールプラス（架空企業）を対象とする。

同社は日用品・食品・生活雑貨を取り扱う小売企業であり、Excelを中心とした売上・在庫管理を行っているものとする。

初期リリースでは、同社が運営する3店舗のうち1店舗を対象とする。

### 3.3 対象外業務

以下の業務は初期リリースの対象外とする。

- 店舗での会計処理
- POSシステムによる販売処理
- 仕入先への発注処理
- 発注承認ワークフロー
- 仕入先との契約管理
- 請求・支払・会計管理
- 複数店舗間の在庫移動
- 倉庫管理
- 配送管理
- 顧客情報管理
- 商品の賞味期限・ロット・個体番号管理
- 返品・返金に関する専用業務

返品や廃棄などに伴う在庫数量の変更については、理由を記録した在庫調整によって対応する。

返品に伴う売上金額の訂正や返金処理など、返品・返金専用の業務は対象外とする。

ただし、販売実績および入荷実績の入力誤りに対する訂正処理は対象とする。

入力誤りの訂正と、実際に発生した返品・返金業務を区別する。

## 6. 業務要件

### 6.1 業務要件の管理方針

各業務要件には一意の識別子を付与する。

識別子は `BR-XXX` 形式とし、ビジネス課題、機能要件およびテストケースとの対応関係を管理する。

優先度は以下の区分を使用する。

| 優先度 | 定義                               |
| ------ | ---------------------------------- |
| Must   | 対象リリースにおいて必須となる要件 |
| Should | 実現することが望ましい要件         |
| Could  | 開発状況に応じて実現を検討する要件 |

### 6.3 業務要件詳細

#### BR-001：商品情報の一元管理

商品情報を一元管理し、在庫管理および売上管理において共通の商品情報を利用できること。

商品コード、商品名、カテゴリ、販売価格、仕入価格および取扱状態などの業務上必要な情報を管理できること。

取扱停止後も、過去の販売実績および入出庫履歴を参照できること。

需要予測および発注提案に必要な調達リードタイムや安全在庫などの情報については、v1.0.0で利用できること。

#### BR-002：現在庫の把握

商品ごとの現在庫数量を確認できること。

初期在庫、販売、入荷、在庫調整および実績訂正の結果が現在庫に正しく反映され、業務上の判断に利用できること。

初期在庫未登録と現在庫数量0を区別できること。

v1.0.0では、入荷予定に関連する入荷実績についても現在庫との整合性を維持できること。

#### BR-003：入出庫履歴の把握

商品ごとの在庫変動について、業務日付、記録日時、変動数量、変動理由および関連する業務情報を確認できること。

在庫変動前後の数量および関連する業務記録を確認できること。

在庫数に不一致が発生した場合に、原因の調査に必要な履歴を参照できること。

入力誤りの訂正時には、元の履歴および訂正履歴を保持すること。

v1.0.0では、関連する入荷予定との対応関係を確認できること。

#### BR-004：販売実績の効率的な登録

販売実績を商品別・日別の単位で効率的に登録できること。

CSVファイルによる一括登録に対応し、同一の販売実績の重複登録や不正なデータの登録を防止できること。

登録前にCSVの検証結果および登録予定内容を確認できること。

通常の販売実績と、現在庫に影響を与えない過去の販売実績を区別して取り扱えること。

入力誤りが判明した場合は、元の記録を保持したうえで訂正、取消および取消解除を行えること。

#### BR-005：売上・在庫状況の可視化

店舗全体および商品ごとの売上・在庫状況を確認できること。

売上金額、販売数量、現在庫数量および概算在庫金額などの業務上必要な指標を把握できること。

売上指標には訂正後の有効な販売実績を使用し、取消済みの販売実績を集計対象外とすること。

v1.0.0では、売上推移、商品別売上、期間比較および販売ランキングなど、より詳細な分析を可能とする。

#### BR-006：将来の商品需要の予測

過去の有効な販売実績を利用し、商品ごとの将来需要を日単位で予測できること。

予測基準日の翌日から14日間の需要予測を行えること。

予測対象期間、予測数量、予測実行状態、予測結果の有効性および予測に必要なデータの充足状況を確認できること。

予測に使用した販売実績が変更された場合は、既存の予測結果への影響を確認できること。

予測結果は実際の需要を保証するものではないことを明示する。

#### BR-007：欠品リスクの把握

現在庫、予測需要および入荷予定に基づき、将来在庫推移を推定できること。

将来的に欠品または安全在庫割れが発生する可能性がある商品を把握できること。

欠品リスクが検出される時期を確認し、発注判断に利用できること。

必要な情報が不足している場合は、判定不可とリスク検出なしを区別できること。

#### BR-008：発注数量の提案

予測需要、現在庫、調達リードタイム、発注間隔、安全在庫および入荷予定に基づき、商品ごとの推奨発注数量を確認できること。

有効な予測結果や必要な発注条件が存在しない場合は、根拠のない発注数量を提示しないこと。

推奨発注数量は意思決定支援のための情報とし、最終的な発注数量は担当者が決定する。

#### BR-009：発注判断の根拠の確認

推奨発注数量の算出に使用された業務情報および算出根拠を確認できること。

少なくとも、現在庫数量、対象期間の予測需要、安全在庫、入荷予定数量および調達リードタイムを確認できること。

予測データが不足している場合、入荷遅延が存在する場合、または通常の発注では欠品を回避できない可能性がある場合は、その旨を把握できること。

発注提案が算出できない場合は、その理由を確認できること。

#### BR-010：需要予測と業務改善効果の評価

需要予測の精度をベースラインモデルと比較し、定量的に評価できること。

また、従来の発注方式とStockPilotによる発注提案方式を比較し、欠品率、平均在庫金額および発注作業時間への影響を検証できること。

評価条件、評価結果、目標達成状況、評価上の制約および改善方針を記録できること。

評価結果は分析Notebookや評価レポートなどの成果物として確認できること。

評価処理をWebアプリ上で実行することは必須としない。

KPIの目標達成状況と分析・評価成果物の完成判定は区別する。

#### BR-011：入荷予定の把握

担当者がシステム外で発注した商品について、入荷予定日および予定数量を管理できること。

入荷済み数量、未入荷数量および取消数量を区別できること。

部分入荷、予定変更、未入荷分の取消および入荷遅延に対応できること。

入荷実績および入荷実績訂正に伴い、関連する入荷予定の数量および状態の整合性を維持できること。

有効な未入荷分を発注判断に利用できること。

入荷予定の登録、変更および取消は現在庫の変更を伴わないものとする。

## 7. 業務ルール

### 7.1 業務ルールの管理方針

各業務ルールには `BRL-XXX` 形式の一意の識別子を付与する。

一度付与した識別子は、原則として変更または再利用しない。

既存の業務ルールを具体化する場合は、識別子を維持したまま記述を更新する。

新たな業務ルールを定義する場合は、新しい識別子を付与する。

業務ルールは機能要件、データ設計およびテストケースの定義に利用する。

業務上の制約および判断基準は本書で管理し、具体的な入力形式、画面仕様、処理手順および受入条件は機能要件定義書で管理する。

具体的な技術的実現方式については、非機能要件定義および基本設計で決定する。

### 7.3 在庫管理に関する補足

現在庫は、初期在庫およびその後に発生した在庫変動の結果として管理する。

店舗単位の在庫管理開始日と商品単位の在庫管理開始日を区別する。

商品単位の在庫管理開始日の営業開始前の在庫数量を初期在庫として登録する。

初期在庫未登録の商品と、初期在庫登録済みで現在庫数量が0の商品を区別する。

在庫変動の種類は以下とする。

| 在庫変動の種類 | 在庫数量への影響             |
| -------------- | ---------------------------- |
| 初期在庫登録   | 初期在庫数量の設定           |
| 入荷           | 増加                         |
| 販売           | 減少                         |
| 在庫増加調整   | 増加                         |
| 在庫減少調整   | 減少                         |
| 入荷実績訂正   | 訂正差分による増加または減少 |
| 販売実績訂正   | 訂正差分による増加または減少 |

初期在庫登録では、登録数量が0の場合も在庫変動履歴を記録する。

初期在庫登録を除き、在庫数量に変動がない操作では在庫変動履歴を追加しない。

現在庫数量が負になる操作は成立させない。

現在庫数量の直接上書きおよび登録済み在庫変動履歴の直接編集・削除は認めない。

入力誤りが判明した場合は、元の業務記録を保持し、理由を記録した訂正処理または在庫調整によって対応する。

入荷実績訂正では、以下の差分を現在庫に反映する。

入荷実績の訂正差分 = 訂正後入荷数量 - 訂正前有効入荷数量

通常販売実績の訂正では、以下の差分を現在庫に反映する。

販売実績の訂正差分 = 訂正前有効販売数量 - 訂正後有効販売数量

在庫変動の業務日付とシステムへの記録日時は区別する。

過去の業務日付を持つ在庫変動についても、現在庫への反映は処理確定順に行う。

任意の過去時点における正確な在庫数量の再構築は、v1.0.0までの必須要件としない。

現在の概算在庫金額は、商品ごとの現在庫数量と現在の商品マスタの仕入価格を乗じた金額の合計とする。

概算在庫金額は業務判断のための参考値であり、会計上の棚卸資産評価額とは区別する。

詳細な登録条件、訂正条件および例外処理は、機能要件定義書に従う。

### 7.4 販売実績の登録区分

販売実績の登録は以下の2種類に区分する。

| 登録区分     | 対象業務日付                 | 用途                                     | 売上データへの反映 | 現在庫への反映 |
| ------------ | ---------------------------- | ---------------------------------------- | ------------------ | -------------- |
| 通常販売実績 | 商品単位の在庫管理開始日以降 | 日常業務における販売実績の登録           | あり               | あり           |
| 過去販売実績 | 商品単位の在庫管理開始日前   | 導入前の販売実績や予測用データの取り込み | あり               | なし           |

いずれの登録区分も、対象商品の初期在庫登録が完了していることを必要とする。

販売実績は商品別・日別の単位で管理する。

同一商品・同一販売日の販売実績について、登録区分および取消状態を問わず重複登録を認めない。

販売実績には実際の販売数量および売上金額を記録する。

CSVによる販売実績の一括登録は、全件成功または全件失敗とする。

通常販売実績の登録では、CSV内の商品別販売数量の合計に基づいて現在庫の不足を判定する。

登録済みの販売実績に誤りがある場合は、以下の操作によって対応する。

| 操作     | 内容                                                     |
| -------- | -------------------------------------------------------- |
| 内容訂正 | 有効な販売実績の販売数量および売上金額を訂正する         |
| 取消     | 販売実績を無効化し、売上集計および需要予測の対象外とする |
| 取消解除 | 取消済みの販売実績を有効な状態に戻す                     |

いずれの操作においても、元の販売実績および変更履歴を保持する。

通常販売実績の訂正、取消および取消解除では、有効販売数量の変更差分を現在庫に反映する。

過去販売実績の訂正、取消および取消解除では、現在庫を変更しない。

販売実績の訂正によって、元の商品、販売日および登録区分を直接変更しない。

有効な販売数量0の実績、未登録の販売実績および取消済みの販売実績は異なる状態として取り扱う。

売上集計および需要予測には、元の販売日を基準として訂正後の有効な販売実績を使用する。

CSVの具体的な項目、入力形式、検証方法および訂正処理の詳細は、機能要件定義書に従う。

### 7.5 入荷予定管理

入荷予定は、担当者がシステム外で実施した発注に基づいて登録する。

入荷予定には、対象商品、入荷予定日、入荷予定数量、入荷済み数量、未入荷数量および取消数量などの業務情報を含める。

入荷予定の登録、変更および取消のみでは現在庫を変更しない。

実際の入荷実績を登録した時点で現在庫を増加させる。

対応する入荷予定が存在する場合は、担当者が入荷実績と入荷予定を関連付ける。

対応する入荷予定が存在しない入荷実績についても登録を許容する。

入荷予定に関連付ける入荷数量は未入荷数量を超えてはならない。

入荷予定の状態は以下の4種類とする。

| 状態         | 定義                                                          |
| ------------ | ------------------------------------------------------------- |
| 入荷予定     | 取消されておらず、入荷済み数量が0であり、未入荷数量が存在する |
| 一部入荷済み | 取消されておらず、一部が入荷済みであり、未入荷数量が存在する  |
| 入荷完了     | 取消されておらず、入荷済み数量が入荷予定数量と一致する        |
| 取消済み     | 未入荷分の取消が確定している                                  |

取消されていない入荷予定では、以下の数量関係を維持する。

入荷予定数量 = 入荷済み数量 + 未入荷数量

取消済みの入荷予定では、以下の数量関係を維持する。

入荷予定数量 = 入荷済み数量 + 取消数量

取消済みの入荷予定における有効な未入荷数量は0とする。

部分入荷後に入荷予定を取り消した場合は、すでに入荷した数量および入荷履歴を保持する。

入荷完了および取消済みの入荷予定は、通常の変更・取消操作の対象外とする。

ただし、取消されていない入荷予定に関連する入荷実績の誤登録を訂正する場合は、訂正後の有効な入荷済み数量に基づいて状態を再判定する。

入荷完了から一部入荷済みまたは入荷予定へ戻る場合がある。

取消済みの入荷予定に関連する入荷実績の訂正は、v1.0.0の通常操作では認めない。

入荷実績、訂正記録、現在庫、入出庫履歴および入荷予定の関連する更新は一体として成立させる。

入荷予定日が現在の業務日付より前であり、有効な未入荷数量が存在する場合は入荷遅延とする。

入荷予定日当日は入荷遅延としない。

入荷遅延は独立した入荷予定状態ではなく、入荷予定に付随する情報として管理する。

入荷遅延のみを理由として、入荷予定日の自動変更または入荷予定の自動取消を行わない。

入荷完了、取消済みおよび入荷遅延中の未入荷数量は、将来在庫推移および発注提案の計算対象外とする。

詳細な業務手順、状態遷移および例外処理については、業務フロー定義書および機能要件定義書を参照する。

### 7.6 需要予測および発注判断

#### 7.6.1 需要予測

需要予測は商品別・日別の粒度で実施する。

業務利用時の予測基準日は、日本時間における前日とする。

予測基準日の翌日から14日間の需要を予測する。

需要予測には、予測基準日以前の有効な通常販売実績および過去販売実績を利用する。

販売実績の未登録を無条件に販売数量0として扱わない。

需要予測は利用者による手動実行を基本とする。

予測に使用した販売実績が変更された場合は、既存の予測結果の有効性を再判定する。

現在の業務判断に必要な条件を満たさない予測結果は、将来在庫推移および発注提案に使用しない。

#### 7.6.2 将来在庫推移

将来在庫推移は、算出時点の現在庫を起点として、予測需要および有効な未入荷数量を日別に反映して算出する。

当日の残存予測需要は、以下の式で算出する。

当日の残存予測需要 = max(0, 当日の予測需要 - 当日の有効な登録済み販売数量)

当日の登録済み販売数量および入荷済み数量を二重に反映しない。

入荷予定日当日の入荷は、その日の残存需要の消費より先に行われるものと仮定する。

将来在庫推移における負数は計算上の累積不足を示すものであり、実際の現在庫数量や販売機会損失数量とは区別する。

#### 7.6.3 欠品リスク

欠品リスクの判定区分は以下とする。

| 判定区分               | 判定方針                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| 欠品リスクあり         | 現在庫が0、または推定在庫数量が0以下となる日が存在する                                       |
| 安全在庫割れリスクあり | 欠品リスクに該当せず、必要な情報が揃っており、現在庫または推定在庫数量が安全在庫数量を下回る |
| リスク検出なし         | 必要な情報が揃っており、上記のリスクが検出されない                                           |
| 判定不可               | 必要な情報が不足し、判定を確定できない                                                       |

現在庫が0の場合は、需要予測の有無にかかわらず欠品リスクありとする。

有効な需要予測が存在しない場合に、将来の欠品リスクが存在しないと判断してはならない。

初期在庫未登録と現在庫数量0を区別する。

判定結果は業務判断のための推定情報であり、実際の欠品の発生を保証するものではない。

#### 7.6.4 発注判断

発注判断は原則として1日1回行うものとする。

発注提案には以下の情報を利用する。

- 現在庫数量
- 当日の残存予測需要
- 翌日以降の予測需要
- 調達リードタイム
- 発注見直し間隔
- 安全在庫
- 入荷予定日
- 有効な未入荷数量

発注判断対象日数は、調達リードタイムと発注見直し間隔の合計とする。

通常の新規発注による最短入荷日は、算出基準日に調達リードタイムを加えた日とする。

推奨発注数量は、必要在庫数量に対する不足分および最短入荷日以降の日別在庫推移を考慮して算出する。

推奨発注数量は0以上の整数とし、算出時に必要数量の小数点以下を切り上げる。

具体的な算出方法は、機能要件定義書のFR-052に従う。

算出方式の妥当性は、在庫シミュレーションによって検証する。

発注提案の区分は以下とする。

| 区分         | 内容                                           |
| ------------ | ---------------------------------------------- |
| 発注推奨     | 推奨発注数量が1以上                            |
| 発注不要     | 推奨発注数量が0                                |
| 発注提案不可 | 必要な情報が不足し、推奨発注数量を算出できない |

発注不要は欠品リスクが存在しないことを保証するものではない。

通常の新規発注による最短入荷日より前に欠品リスクが存在する場合は、通常発注では間に合わない可能性を明示する。

入荷遅延中の未入荷数量は利用可能在庫に含めず、入荷状況の確認を案内する。

発注提案によって現在庫および入荷予定を自動変更しない。

最終的な発注判断は担当者が行い、仕入先への実際の発注はシステム外で行う。

## 9. 業務評価指標（KPI）

### 9.1 評価指標

プロジェクト企画書で定義したKPIを引き継ぐ。

| ID      | 評価指標            | 目標値                              |
| ------- | ------------------- | ----------------------------------- |
| KPI-001 | 欠品率              | 従来方式と比較して20%削減           |
| KPI-002 | 平均在庫金額        | 従来方式と比較して15%削減           |
| KPI-003 | 発注作業時間        | 従来方式と比較して50%削減           |
| KPI-004 | 需要予測誤差（MAE） | ベースラインモデルと比較して10%改善 |

上記は企画段階で設定した暫定的な目標値であり、実際の改善効果を保証するものではない。

### 9.2 評価方法

| KPI     | 評価方法                                                 | 比較対象                       |
| ------- | -------------------------------------------------------- | ------------------------------ |
| KPI-001 | 在庫・発注シミュレーションによる数量ベースの欠品率の比較 | 従来方式とStockPilot方式       |
| KPI-002 | 同一条件下での平均在庫金額の比較                         | 従来方式とStockPilot方式       |
| KPI-003 | 模擬業務による発注作業時間の測定                         | 従来方式とStockPilot方式       |
| KPI-004 | 時系列を考慮した需要予測精度の評価                       | ベースラインモデルと提案モデル |

各KPIの基本的な算出方法は以下とする。

#### KPI-001：欠品率

欠品率 = 需要を満たせなかった数量の合計 / 総需要数量

数量ベースの欠品率を採用する。

需要を満たせなかった数量は、在庫シミュレーションにおける販売機会損失数量として取り扱う。

将来在庫推移における計算上の累積不足数量を、そのまま実際の販売機会損失数量として使用しない。

#### KPI-002：平均在庫金額

日別在庫金額 = 各商品の日末在庫数量と評価用仕入単価を乗じた金額の合計

平均在庫金額 = 評価期間内の日別在庫金額の平均

比較対象間で同一の評価用仕入単価を使用する。

#### KPI-003：発注作業時間

同等の業務条件において、発注判断に必要な情報の確認、発注数量の決定および発注結果の記録に要する時間を測定する。

仕入先への実際の発注に要する時間は評価対象外とする。

#### KPI-004：需要予測誤差（MAE）

MAE = 予測値と実測値の絶対誤差の平均

ベースラインモデルと提案モデルを共通の評価対象に基づいて比較する。

予測可能な対象範囲および評価対象から除外されたデータについても記録する。

#### 共通の改善率

改善率（%）= (比較基準値 - 評価対象値) / 比較基準値 × 100

比較基準値が0の場合は、改善率を算出不可として扱う。

各指標の分母が0となる場合も、当該指標を算出不可として扱う。

算出不可を改善率0%または目標達成として扱わない。

欠品率と平均在庫金額にはトレードオフが存在するため、各指標を個別に評価するだけでなく、総合的な業務改善効果を評価する。

詳細な評価方法、評価条件および成果物の要件は、機能要件定義書のAR-001〜AR-007に従う。

### 9.3 評価結果の取り扱い

KPIの目標値は、需要予測精度および業務改善効果を評価するための暫定的な目標値とする。

評価結果が目標値に達しなかった場合は、原因および改善策を分析する。

目標値の達成有無にかかわらず、評価条件、評価結果、評価上の制約および今後の改善方針を記録する。

評価に必要なデータを取得できない場合や測定を実施できない場合は、その理由を明示する。

未測定の指標について、実測値または改善実績を作成してはならない。

KPIの目標達成状況と、分析・評価成果物の完成判定は区別する。

KPIの未達成のみを理由として、プロジェクト全体を未完成とは判定しない。

ただし、必須の分析・評価作業を実施していない場合は、原則として当該成果物要件を未完了として扱う。

実際の企業における導入効果と、シミュレーションまたは模擬業務による評価結果を混同しないものとする。

## 11. 前提条件および制約事項

### 11.1 前提条件

- 想定顧客企業および業務課題は架空の設定である。
- 対象店舗では商品コードによる商品識別が可能であるものとする。
- 販売実績をCSVファイルとして取得できるものとする。
- システム導入時に初期在庫数量を把握できるものとする。
- 商品ごとの調達リードタイムおよび安全在庫を設定できるものとする。
- 担当者が発注結果および入荷実績を適切に登録するものとする。
- 最終的な発注判断は担当者が行うものとする。
- システム運用担当者が利用者のアカウントを事前に準備するものとする。
- 店舗および商品単位の在庫管理開始日を適切に設定できるものとする。
- 商品別・日別の販売数量および実際の売上金額を取得できるものとする。
- 入荷予定に変更または遅延が生じた場合は、担当者が実際の状況を確認するものとする。

### 11.2 制約事項

- 個人開発として実施する。
- 初期リリースでは単一店舗のみを対象とする。
- 実際の企業システムとの連携は行わない。
- 実在する企業の機密情報や個人情報は使用しない。
- 公開データまたは合成データを使用する。
- 外部データの利用規約およびライセンスを遵守する。
- 開発・運用費用は原則として無料の範囲に収める。
- 需要予測の結果は将来の需要を保証するものではない。
- 一般公開のユーザー登録はv1.0.0までの対象外とする。
- 商品情報の物理削除および入出庫履歴の直接編集・削除を行わない。
- 会計上の棚卸資産評価額の算出は対象外とする。
- 任意の過去時点における正確な在庫数量の再構築は必須としない。

### 11.3 データに関する制約

販売実績は実際に販売された数量を示すものであり、必ずしも潜在的な需要数量と一致しない。

特に、欠品が発生している期間の販売数量は、実際の需要を過小評価している可能性がある。

需要予測および業務改善効果の評価においては、この制約を考慮し、利用するデータの限界を明示する。

販売実績の未登録、販売数量0および取消済みの販売実績は区別して取り扱う。

データ分析および需要予測において、未登録の販売実績を無条件に販売数量0として補完しない。

欠品による販売機会損失数量を直接取得できない場合は、利用可能なデータおよび評価上の仮定を明示する。

在庫シミュレーションにおいて販売実績を需要数量の代理値として使用する場合は、その制約を評価結果に記録する。

シミュレーション上の業務改善効果を、実際の企業への導入による改善実績として扱わない。

## 12. 未決事項

### 12.1 管理方針

業務要件定義工程で発生した未決事項について、一意の識別子を付与して管理する。

未決事項の状態は、決定済み、一部決定および未決定の3種類とする。

決定済みとなった事項についても、識別子および決定内容を保持する。

詳細な機能仕様および技術的な未決事項は、機能要件定義書などの関連ドキュメントで管理する。

### 12.3 関連ドキュメントでの管理

業務フロー定義工程で発生した未決事項については、業務フロー定義書を参照する。

機能要件定義工程で発生した未決事項については、機能要件定義書を参照する。

同一の未決事項を複数のドキュメントで管理する場合は、関連する識別子を記録し、決定状況および決定内容の整合性を維持する。

未決事項については、関連する工程で決定内容を記録し、必要に応じて本書を改訂する。

## 13. 業務要件の完了条件

以下の条件を満たすことを業務要件定義の完了条件とする。

- 対象業務および対象外業務が明確であること。
- 想定利用者および業務上の役割が明確であること。
- ビジネス課題と業務要件の対応関係が明確であること。
- 業務要件に一意の識別子が付与されていること。
- 業務ルールに一意の識別子が付与されていること。
- リリースごとの対象範囲が明確であること。
- KPIおよび評価方針が定義されていること。
- 前提条件、制約事項および未決事項が明記されていること。
- プロジェクト企画書との差異および変更理由が記録されていること。
- 後続の機能要件定義および基本設計に利用できること。

## 14. 用語定義

| 用語                     | 定義                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| 現在庫                   | 現時点におけるシステム上の在庫数量                                   |
| 初期在庫                 | 商品単位の在庫管理開始日の営業開始前における在庫数量                 |
| 入庫                     | 商品の在庫数量が増加すること                                         |
| 出庫                     | 商品の在庫数量が減少すること                                         |
| 在庫調整                 | 実在庫とシステム上の在庫数量の不一致などを訂正する処理               |
| 欠品                     | 需要に対して供給可能な在庫が不足する状態                             |
| 過剰在庫                 | 業務上必要な水準を超えて在庫を保有する状態                           |
| 需要予測                 | 過去のデータなどから将来の商品需要を推定すること                     |
| 調達リードタイム         | 商品の発注から入荷までに要する期間                                   |
| 発注間隔                 | 発注判断を行う間隔                                                   |
| 安全在庫                 | 需要変動や調達の不確実性に備えて確保する在庫                         |
| 入荷予定                 | 発注済みで今後入荷する予定の商品および数量                           |
| 推奨発注数量             | 業務情報および予測需要に基づきシステムが提案する発注数量             |
| ベースラインモデル       | 予測モデルの性能を比較するための基準となるモデル                     |
| MAE                      | 平均絶対誤差。予測値と実測値の絶対誤差の平均                         |
| トレーサビリティ         | ビジネス課題、要件、設計、実装およびテストの対応関係を追跡できること |
| 店舗の在庫管理開始日     | 店舗全体におけるStockPilotでの在庫管理開始日の基準                   |
| 商品単位の在庫管理開始日 | 商品ごとの初期在庫および販売実績の登録区分を決定する基準日           |
| 通常販売実績             | 商品単位の在庫管理開始日以降の販売実績であり、現在庫に反映するもの   |
| 過去販売実績             | 商品単位の在庫管理開始日前の販売実績であり、現在庫に反映しないもの   |
| 有効販売実績             | 取消されていない販売実績                                             |
| 有効販売数量             | 訂正および取消状態を反映した現在の販売数量                           |
| 有効入荷数量             | 訂正履歴を反映した現在の入荷数量                                     |
| 業務日付                 | 販売や入荷などの業務上の事象が発生した日付                           |
| 記録日時                 | 業務データがシステムに記録された日時                                 |
| 訂正差分                 | 訂正前後の有効数量の差に基づく在庫数量の変更量                       |
| 概算在庫金額             | 現在庫数量と現在の商品マスタの仕入価格に基づく参考金額               |
| 入荷済み数量             | 入荷予定に関連する有効な入荷実績の数量合計                           |
| 未入荷数量               | 入荷予定のうち、まだ入荷しておらず取消されていない数量               |
| 取消数量                 | 入荷予定の未入荷分のうち、取消が確定した数量                         |
| 入荷遅延                 | 入荷予定日を過ぎても有効な未入荷数量が存在する状態                   |
| 予測基準日               | 需要予測に利用する実績データの基準となる日付                         |
| 有効予測結果             | 現在の業務判断に必要な条件を満たしている需要予測結果                 |
| 要再予測                 | 予測入力に影響する変更などにより、再度の需要予測が必要な状態         |
| 残存予測需要             | 当日の予測需要から登録済み販売数量を差し引いた0以上の需要数量        |
| 将来在庫推移             | 現在庫、予測需要および入荷予定に基づく日別在庫数量の推定結果         |
| 安全在庫割れ             | 現在庫または推定在庫数量が設定された安全在庫数量を下回ること         |
| 販売機会損失             | 在庫不足などによって需要を満たせず、販売が成立しないこと             |
