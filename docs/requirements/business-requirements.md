## 2. 本書の目的

本書は、StockPilotのプロジェクト企画書に基づき、想定顧客企業のビジネス課題を解決するために必要な業務要件および業務ルールを定義することを目的とする。

本書で定義した業務要件は、後続の業務フロー定義、機能要件定義、非機能要件定義、基本設計およびテストの基礎とする。

なお、想定顧客企業および業務上の要求は架空の設定であり、実際の顧客へのヒアリングに基づくものではない。

## 3. 対象業務

### 3.1 対象企業

プロジェクト企画書で定義した株式会社リテールプラス（架空企業）を対象とする。

同社は日用品・食品・生活雑貨を取り扱う小売企業であり、Excelを中心とした売上・在庫管理を行っているものとする。

初期リリースでは、同社が運営する3店舗のうち1店舗を対象とする。

### 3.3 対象外業務

以下の業務は初期リリースの対象外とする。

- 店舗での会計処理
- POSシステムによる販売処理
- 仕入先への発注処理
- 発注承認ワークフロー
- 仕入先との契約管理
- 請求・支払・会計管理
- 複数店舗間の在庫移動
- 倉庫管理
- 配送管理
- 顧客情報管理
- 商品の賞味期限・ロット・個体番号管理
- 返品・返金に関する専用業務

返品や廃棄などに伴う在庫数量の変更については、理由を記録した在庫調整によって対応する。ただし、返品に伴う売上金額の訂正や返金処理は対象外とする。

## 6. 業務要件

### 6.1 業務要件の管理方針

各業務要件には一意の識別子を付与する。

識別子は `BR-XXX` 形式とし、ビジネス課題、機能要件およびテストケースとの対応関係を管理する。

| ------ | ---------------------------------- |
| Must   | 対象リリースにおいて必須となる要件 |
| Should | 実現することが望ましい要件         |
| Could  | 開発状況に応じて実現を検討する要件 |

### 6.3 業務要件詳細

#### BR-001：商品情報の一元管理

商品情報を一元管理し、在庫管理および売上管理において共通の商品情報を利用できること。

商品コード、商品名、カテゴリ、販売価格、仕入価格および取扱状態などの業務上必要な情報を管理できること。

需要予測および発注提案に必要な調達リードタイムや安全在庫などの情報については、v1.0.0で利用できること。

#### BR-002：現在庫の把握

商品ごとの現在庫数量を確認できること。

販売、入荷および在庫調整の結果が現在庫に反映され、業務上の判断に利用できること。

#### BR-003：入出庫履歴の把握

商品ごとの在庫変動について、発生日時、変動数量、変動理由および関連する業務情報を確認できること。

在庫数に不一致が発生した場合に、原因の調査に必要な履歴を参照できること。

#### BR-004：販売実績の効率的な登録

販売実績を効率的に登録できること。

CSVファイルによる一括登録に対応し、同一の販売実績の重複登録や不正なデータの登録を防止できること。

通常の販売実績と、現在庫に影響を与えない過去の販売実績を区別して取り扱えること。

#### BR-005：売上・在庫状況の可視化

店舗全体および商品ごとの売上・在庫状況を確認できること。

売上金額、販売数量、現在庫数量および在庫金額などの業務上必要な指標を把握できること。

v1.0.0では、売上の推移や商品別の販売傾向など、より詳細な分析を可能とする。

#### BR-006：将来の商品需要の予測

過去の販売実績を利用し、商品ごとの将来需要を日単位で予測できること。

予測対象期間、予測数量および予測に必要なデータの充足状況を確認できること。

予測結果は実際の需要を保証するものではないことを明示する。

#### BR-007：欠品リスクの把握

現在庫、予測需要および入荷予定に基づき、将来的に欠品する可能性がある商品を把握できること。

欠品が予想される時期を確認し、発注判断に利用できること。

#### BR-008：発注数量の提案

予測需要、現在庫、調達リードタイム、発注間隔、安全在庫および入荷予定に基づき、商品ごとの推奨発注数量を確認できること。

推奨発注数量は意思決定支援のための情報とし、最終的な発注数量は担当者が決定する。

#### BR-009：発注判断の根拠の確認

推奨発注数量の算出に使用された業務情報を確認できること。

少なくとも、現在庫数量、対象期間の予測需要、安全在庫、入荷予定数量および調達リードタイムを確認できること。

予測データが不足している場合や、欠品が回避できない可能性がある場合は、その旨を把握できること。

#### BR-010：需要予測と業務改善効果の評価

需要予測の精度をベースラインモデルと比較し、定量的に評価できること。

また、従来の発注方式とStockPilotによる発注提案方式を比較し、欠品率、平均在庫金額および発注作業時間への影響を検証できること。

評価結果は分析Notebookや評価レポートなどの成果物として確認できること。

評価処理をWebアプリ上で実行することは必須としない。

#### BR-011：入荷予定の把握

担当者がシステム外で発注した商品について、入荷予定日および予定数量を管理できること。

入荷済み数量と未入荷数量を区別し、未入荷分を発注判断に利用できること。

入荷予定の登録は現在庫への加算を伴わないものとする。

### 7.3 在庫管理に関する補足

現在庫は、初期在庫およびその後に発生した在庫変動の結果として管理する。

在庫変動の主な種類は以下とする。

| 在庫変動の種類   | 在庫数量への影響 |
| ---------------- | ---------------- |
| 初期在庫登録     | 増加             |
| 入荷             | 増加             |
| 販売             | 減少             |
| 在庫調整（増加） | 増加             |
| 在庫調整（減少） | 減少             |

在庫数量が負になる操作は成立させない。

登録済みの在庫変動に誤りがある場合は、元の履歴を保持し、理由を記録した訂正処理によって対応する。

販売実績に誤りがある場合の訂正方法については、機能要件定義において具体化する。

### 7.4 販売実績の登録区分

販売実績の登録は以下の2種類に区分する。

| 登録区分       | 用途                                     | 売上データへの反映 | 現在庫への反映 |
| -------------- | ---------------------------------------- | ------------------ | -------------- |
| 通常登録       | 日常業務における販売実績の登録           | あり               | あり           |
| 過去データ登録 | 導入前の販売実績や予測用データの取り込み | あり               | なし           |

過去データ登録は、現在庫に販売結果がすでに反映されているデータを対象とする。

通常登録と過去データ登録の区分を利用して、同一の販売実績を重複登録することは認めない。

具体的な重複判定方法および登録可能な業務日付の条件は、機能要件定義において定義する。

### 7.5 入荷予定管理

入荷予定は、担当者がシステム外で実施した発注に基づいて登録する。

入荷予定には、対象商品、入荷予定日、予定数量および未入荷数量などの業務情報を含める。

入荷予定の登録時点では現在庫を変更せず、実際の入荷実績を登録した時点で現在庫を増加させる。

一部のみ入荷した場合は、残りの未入荷数量を管理する。

入荷予定を取り消した場合は、取消分を発注提案の計算対象から除外する。

### 7.6 需要予測および発注判断

需要予測は商品別・日別の粒度で実施する。

発注判断は原則として1日1回行うものとし、調達リードタイムと発注間隔を考慮して必要な在庫数量を算出する。

発注提案には以下の情報を利用する。

- 現在庫数量
- 予測需要
- 調達リードタイム
- 発注間隔
- 安全在庫
- 入荷予定日
- 未入荷数量

推奨発注数量は、必要在庫数量に対する不足分を基礎として算出する。

入荷予定については数量だけでなく、入荷予定日も考慮する。

調達リードタイム内に欠品する可能性がある場合は、通常の発注によって欠品を回避できない可能性があることを示す。

具体的な算出方法、端数処理、欠品リスクの判定基準および予測データ不足時の取り扱いについては、後続工程で定義する。

### 8.1 基本仕様

| 項目             | 仕様          |

| 項目               | 仕様                         |
| ------------------ | ---------------------------- |
| 需要予測の粒度     | 商品別・日別                 |
| 需要予測期間       | 14日間                       |
| 発注判断の頻度     | 原則1日1回                   |
| 調達リードタイム   | 商品ごとに1〜7日の範囲で設定 |

| 安全在庫           | 商品ごとに設定               |

## 9. 業務評価指標（KPI）

### 9.1 評価指標

プロジェクト企画書で定義したKPIを引き継ぐ。

| ID      | 評価指標            | 目標値                              |
| ------- | ------------------- | ----------------------------------- |
| KPI-001 | 欠品率              | 従来方式と比較して20%削減           |
| KPI-002 | 平均在庫金額        | 従来方式と比較して15%削減           |
| KPI-003 | 発注作業時間        | 従来方式と比較して50%削減           |
| KPI-004 | 需要予測誤差（MAE） | ベースラインモデルと比較して10%改善 |

上記は企画段階で設定した暫定的な目標値であり、実際の改善効果を保証するものではない。

### 9.2 評価方法

| KPI     | 評価方法                         |
| ------- | -------------------------------- |
| KPI-001 | 在庫・発注シミュレーション       |
| KPI-002 | 同一条件下での在庫金額の比較     |
| KPI-003 | 模擬業務による発注作業時間の測定 |
| KPI-004 | 時系列を考慮した予測精度の評価   |

比較対象となる従来方式、ベースラインモデル、評価期間、評価データおよび具体的な計算方法は後続工程で定義する。

欠品率と平均在庫金額にはトレードオフが存在するため、各指標を個別に評価するだけでなく、総合的な業務改善効果を評価する。

### 9.3 評価結果の取り扱い

評価結果が目標値に達しなかった場合は、原因および改善策を分析する。

目標値の達成有無にかかわらず、評価条件、評価結果および検証上の限界を記録する。

実際の企業における導入効果と、シミュレーションによる評価結果を混同しないものとする。

## 11. 前提条件および制約事項

### 11.1 前提条件

- 想定顧客企業および業務課題は架空の設定である。
- 対象店舗では商品コードによる商品識別が可能であるものとする。
- 販売実績をCSVファイルとして取得できるものとする。
- システム導入時に初期在庫数量を把握できるものとする。
- 商品ごとの調達リードタイムおよび安全在庫を設定できるものとする。
- 担当者が発注結果および入荷実績を適切に登録するものとする。
- 最終的な発注判断は担当者が行うものとする。

### 11.2 制約事項

- 個人開発として実施する。
- 初期リリースでは単一店舗のみを対象とする。
- 実際の企業システムとの連携は行わない。
- 実在する企業の機密情報や個人情報は使用しない。
- 公開データまたは合成データを使用する。
- 外部データの利用規約およびライセンスを遵守する。
- 開発・運用費用は原則として無料の範囲に収める。
- 需要予測の結果は将来の需要を保証するものではない。

### 11.3 データに関する制約

販売実績は実際に販売された数量を示すものであり、必ずしも潜在的な需要数量と一致しない。

特に、欠品が発生している期間の販売数量は、実際の需要を過小評価している可能性がある。

需要予測および業務改善効果の評価においては、この制約を考慮し、利用するデータの限界を明示する。

## 13. 業務要件の完了条件

以下の条件を満たすことを業務要件定義の完了条件とする。

- 対象業務および対象外業務が明確であること。
- 想定利用者および業務上の役割が明確であること。
- ビジネス課題と業務要件の対応関係が明確であること。
- 業務要件に一意の識別子が付与されていること。
- 業務ルールに一意の識別子が付与されていること。
- リリースごとの対象範囲が明確であること。
- KPIおよび評価方針が定義されていること。
- 前提条件、制約事項および未決事項が明記されていること。
- プロジェクト企画書との差異および変更理由が記録されていること。
- 後続の機能要件定義および基本設計に利用できること。

## 14. 用語定義

| 用語               | 定義                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| 現在庫             | 現時点におけるシステム上の在庫数量                                   |
| 初期在庫           | システム導入時点における在庫数量                                     |
| 入庫               | 商品の在庫数量が増加すること                                         |
| 出庫               | 商品の在庫数量が減少すること                                         |
| 在庫調整           | 実在庫とシステム上の在庫数量の不一致などを訂正する処理               |
| 欠品               | 需要に対して供給可能な在庫が不足する状態                             |
| 過剰在庫           | 業務上必要な水準を超えて在庫を保有する状態                           |
| 需要予測           | 過去のデータなどから将来の商品需要を推定すること                     |
| 調達リードタイム   | 商品の発注から入荷までに要する期間                                   |
| 発注間隔           | 発注判断を行う間隔                                                   |
| 安全在庫           | 需要変動や調達の不確実性に備えて確保する在庫                         |
| 入荷予定           | 発注済みで今後入荷する予定の商品および数量                           |
| 推奨発注数量       | 業務情報および予測需要に基づきシステムが提案する発注数量             |
| ベースラインモデル | 予測モデルの性能を比較するための基準となるモデル                     |
| MAE                | 平均絶対誤差。予測値と実測値の絶対誤差の平均                         |
| トレーサビリティ   | ビジネス課題、要件、設計、実装およびテストの対応関係を追跡できること |
